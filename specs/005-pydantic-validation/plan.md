# Implementation Plan: Pydantic Validation for Auth Models

**Branch**: `005-pydantic-validation` | **Date**: 2026-03-03 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/005-pydantic-validation/spec.md`

## Summary

Replace manual dataclass validation in `auth/models.py` with Pydantic v2 BaseModel, adding declarative field validation, immutability (frozen), and serialization methods. Introduce a new `TokenResponse` model for parsing WHOOP API responses in a single step. Refactor `token_manager.py` to delegate serialization/deserialization to model methods. All existing public API and test assertions preserved (FR-008, SC-001).

Key design decision: **Do not use `SecretStr`** — it changes the field type from `str` to `SecretStr`, breaking equality comparisons and direct string access in existing code. Use plain `str` with custom `__repr__` masking instead (see research.md, Decision 1).

## Key Design Patterns

### 1. NonEmptyStr Type Alias

```python
from typing import Annotated
from pydantic import Field

NonEmptyStr = Annotated[str, Field(min_length=1)]
```

Used for `client_id`, `client_secret`, `access_token`, `refresh_token` across all models.

### 2. Custom Repr with _mask()

Retain existing `_mask()` helper. Override `__repr__` on models to mask secret fields while keeping plain `str` field types for backward compatibility.

### 3. Explicit Serialization Methods

`to_store_dict()` and `from_store_dict()` on `TokenPair` — explicit methods rather than `@field_serializer` because the monotonic↔UTC conversion depends on runtime state (`time.monotonic()`, `datetime.now(timezone.utc)`).

### 4. Frozen Model Mutation in Tests

Replace `manager._token_pair.expires_at = value` with:
```python
manager._token_pair = manager._token_pair.model_copy(update={"expires_at": value})
```
